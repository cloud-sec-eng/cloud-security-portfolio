# Cloud Security Engineering Portfolio

Enterprise cloud security engineering portfolio featuring Azure, AWS, Terraform, DevSecOps, and infrastructure security.

## Portfolio Mission

This portfolio documents my progression in Cloud Security Engineering through a progressively expanding enterprise-style cloud lab.

The primary focus is Azure security architecture, followed by AWS security, infrastructure automation, DevSecOps, and container security.

Projects are designed to demonstrate practical engineering capabilities, including:

- Designing secure cloud infrastructure and network architectures
- Implementing identity, access control, and network segmentation
- Automating infrastructure with Terraform and scripting
- Monitoring security events and investigating misconfigurations
- Testing security controls and documenting validation evidence
- Troubleshooting failures and explaining technical design decisions

The portfolio distinguishes professional experience from independently completed lab projects. Projects are marked complete only after their functionality and security controls have been verified.

## Enterprise Cloud Security Lab — Planned Architecture

The portfolio is organized around a progressively expanding enterprise-style cloud environment designed to simulate real-world infrastructure security challenges.

### Initial Architecture

- **Azure Hub Network:** Centralized security services, routing, firewall inspection, DNS, and connectivity.
- **Development Spoke:** Isolated environment for testing infrastructure changes and security controls.
- **Testing Spoke:** Environment for validating configurations and security policies before promotion.
- **Production-Like Spoke:** Controlled environment simulating production security requirements without hosting real business workloads.
- **Identity & Access:** Microsoft Entra ID, Azure RBAC, managed identities, and least-privilege access.
- **Security Monitoring:** Azure Monitor, Microsoft Defender for Cloud, Microsoft Sentinel, and centralized log collection.
- **Infrastructure Automation:** Terraform, reusable modules, GitHub Actions, and secure CI/CD workflows.

### Future Expansion

The environment will progressively incorporate Docker, Kubernetes, Azure Kubernetes Service (AKS), AWS networking and identity security, and Amazon Elastic Kubernetes Service (EKS).

### Architecture Status

**Planned — Not Deployed**

The architecture will be refined after assessing existing cloud resources, network addressing requirements, identity configurations, security controls, operational costs, and deployment dependencies.
